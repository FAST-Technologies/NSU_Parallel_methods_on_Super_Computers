# Лабораторная работа №2: Гибридное распараллеливание (MPI + OpenMP)
## Решение 3D уравнения Пуассона методом Якоби

Данный репозиторий содержит реализацию и исследование производительности гибридной параллельной программы для решения трёхмерного уравнения Пуассона методом Якоби. Проект разработан в рамках учебного курса по параллельным методам вычислений.

---

## 📋 Описание и внесённые изменения

**Основная цель работы** – практическое освоение методов распараллеливания численных алгоритмов на регулярных сетках с использованием гибридной модели MPI + OpenMP.

**Ключевые особенности реализации:**
1. **Двумерная декомпозиция области**: Пространство разбивается на подобласти по осям X и Y с использованием виртуальной декартовой топологии MPI (`MPI_Cart_create`).
2. **Неблокирующие обмены (Halo Exchange)**: Граничные значения передаются соседям с помощью `MPI_Isend` / `MPI_Irecv`, что позволяет скрыть задержки сети.
3. **Перекрытие вычислений и коммуникаций**: Пока идут асинхронные обмены граничными слоями, OpenMP-потоки вычисляют значения во *внутренних* точках подобласти, не зависящих от границ.
4. **Двойная архитектура сборки**:
   * `Lab_02`: Основная версия с внутренним профилированием через `MPI_Wtime` для точных замеров времени.
   * `Lab_02_mpe`: Специальная версия с настраиваемым профилированием MPE для генерации трассировочных файлов `.clog2` и визуализации в Jumpshot.
5. **Многоуровневая оптимизация**: Внутренние циклы распараллелены с помощью `#pragma omp parallel for collapse(3)` для эффективного использования кэш-памяти и векторизации.
6. **Чистая архитектура**: Код разделён на заголовочный файл (`poisson_solver.hpp`) с документацией Doxygen и файл реализации.
7. **Тройной контроль времени**: Замер времени выполняется одновременно через `MPI_Wtime()`, `omp_get_wtime()` и `std::chrono` для подтверждения корректности метрик.

## 💻 Системные требования

* **ОС:** Linux (протестировано на Ubuntu 24.04 LTS через WSL2)
* **Компилятор:** GCC 13.3.0 (или Clang)
* **Библиотеки:** OpenMPI (`openmpi-bin`, `libopenmpi-dev`), OpenMP (встроен в GCC), MPE2 (опционально, для версии `Lab_02_mpe`)

* **Документация:** Doxygen (опционально, для генерации docs)
* **Скрипты:** Bash (для `benchmark.sh`), Python 3 + `matplotlib`, `seaborn` (для построения графиков)
* **Дополнительно:** утилита `bc` (для работы скрипта бенчмаркинга)

## 🛠️ Сборка проекта

1. Склонируйте репозиторий (если еще не сделали этого):
   ```bash
   git clone <URL этого репозитория>
   cd NSU_Parallel_methods_on_Super_Computers/Lab_02
   ```
2. Создайте директорию для сборки и перейдите в неё:
   ```bash
   mkdir build && cd build
   ```
3. Сконфигурируйте проект в режиме Release (с оптимизацией `-O3`):
   ```bash
   cmake .. -DCMAKE_BUILD_TYPE=Release
   ```
4. Скомпилируйте проект, используя все доступные ядра:
   ```bash
   make -j
   ```
5. Опционально. Сгенерировать Doxygen-документацию:
   ```bash
   make doc
   ```

## 🚀 Запуск и бенчмаркинг
### **Ручной запуск**
Программа принимает три аргумента: размеры сетки по осям X, Y, Z. По умолчанию используется сетка 200×200×200.
   ```bash
   # Запуск основной версии на 4 MPI-процессах
   mpirun --oversubscribe -np 4 ./build/Lab_02 200 200 200
   
   # Запуск MPE-версии для сбора трассировки (сохранит jacobi_profile.clog2)
   mpirun --oversubscribe -np 4 ./build/Lab_02_mpe 200 200 200
   ```

### **Гибридный запуск (Моделирование кластера локально)**

Для поиска оптимальной комбинации «число MPI-процессов × число OpenMP-потоков» используйте переменную окружения `OMP_NUM_THREADS`.
*Пример: 2 MPI-процесса, каждый из которых порождает по 4 OpenMP-потока (всего 8 вычислительных потоков):*

   ```bash
   OMP_NUM_THREADS=4 mpirun -np 2 ./Lab_02 200 200 200
   ```

### **Автоматический гибридный бенчмаркинг**

В корне проекта находится скрипт `benchmark.sh`, который автоматически тестирует различные комбинации MPI-процессов и OpenMP-потоков при фиксированном общем числе потоков, выполняя по 3 запуска для каждой конфигурации и выбирая минимальное время.

   ```bash
   # Сделать скрипт исполняемым (один раз)
   chmod +x benchmark.sh
   
   # Запустить бенчмарк
   ./benchmark.sh
   ```

### **Построение графиков**

   ```bash
   pip install -r requirements.txt   # matplotlib, numpy, seaborn
   python3 visual_scripts/plot_benchmarks2.py
   ```
> **Примечание**: скрипт автоматически ищет исполняемый файл в папке `build/`. Для тестирования на реальном кластере используйте планировщик задач (например, SLURM: `srun -N 4 -n 32 --cpus-per-task=4 ./Lab_02 200 200 200`).

## 📊 Краткие результаты исследования
Эксперименты проводились на сетке размером **200 × 200 × 200** узлов. Ниже приведены реальные замеры времени для конфигураций с фиксированным общим числом вычислительных потоков, равным 12 (выполнено 3 запуска, взято минимальное время).

| **Конфигурация (MPI × OMP)** | **Общее кол-во потоков** |     **Время (сек)**      | **Ускорение $S_{P}$** | **Эффективность $E_{P}$** |
|:-----------------------------|:------------------------:|:------------------------:|:---------------------:|:-------------------------:|
| **12 × 1 (Pure MPI)**        |            12            |       **0.31340**        |       **3.16x**       |         **26.3%**         |
| **6 × 2 (Hybrid)**           |            12            |         0.33480          |         2.96x         |           24.6%           |
| **4 × 3 (Hybrid)**           |            12            |         0.31460          |         3.15x         |           26.2%           |
| **3 × 4 (Hybrid)**           |            12            |         0.31858          |         3.11x         |           25.9%           |
| **2 × 6 (Hybrid)**           |            12            |         0.39326          |         2.51x         |           20.9%           |
| **1 × 12 (Pure OpenMP)**     |            12            |         0.64771          |         1.53x         |           12.7%           |

*(Базовое время для 1 потока (Pure Sequential) составляет ~0.99 сек).*

### **Ключевые выводы:**
1. **Перекрытие работает**: встроенное профилирование и визуализация в Jumpshot подтверждают, что фаза вычисления внутренних точек успешно маскирует задержки `MPI_Waitall`.
2. **Влияние архитектуры**: на локальной машине (WSL2, гибридный CPU) конфигурация `12x1` показала себя оптимальной для данного размера задачи из-за минимизации накладных расходов на создание множества легковесных OpenMP-потоков внутри одного процесса. Однако на реальных многоузловых кластерах гибридные конфигурации (например, `4x3`) демонстрируют лучшую масштабируемость за счет снижения объема межпроцессных MPI-коммуникаций.
3. **Согласованность таймеров**: значения `MPI_Wtime`, `omp_get_wtime` и `std::chrono` отличаются не более чем на 1-2 мс, что подтверждает корректность изоляции вычислительного ядра от I/O операций.
4. **Деградация при Oversubscription**: чрезмерное увеличение числа OpenMP-потоков (например, `1x12`) приводит к резкому падению эффективности из-за конкуренции за ресурсы планировщика ОС и кэш-память

*Полные таблицы данных, графики ускорения и эффективности, а также подробный анализ и скриншоты профиля MPE представлены в [отчёте по лабораторной работе](./Report_on_Assignment_02_Yamshchikov.docx "Отчёт по проделанной работе").*
