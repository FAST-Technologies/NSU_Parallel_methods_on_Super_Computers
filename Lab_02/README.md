# Лабораторная работа №2: Гибридное распараллеливание (MPI + OpenMP)
## Решение 3D уравнения Пуассона методом Якоби

Данный репозиторий содержит реализацию и исследование производительности гибридной параллельной программы для решения трёхмерного уравнения Пуассона методом Якоби. Проект разработан в рамках учебного курса по параллельным методам вычислений.

---

## 📋 Описание и внесённые изменения

**Основная цель работы** – практическое освоение методов распараллеливания численных алгоритмов на регулярных сетках с использованием гибридной модели MPI + OpenMP.

**Ключевые особенности реализации:**
1. **Двумерная декомпозиция области**: Пространство разбивается на подобласти по осям X и Y с использованием виртуальной декартовой топологии MPI (`MPI_Cart_create`).
2. **Неблокирующие обмены (Halo Exchange)**: Граничные значения передаются соседям с помощью `MPI_Isend` / `MPI_Irecv`, что позволяет скрыть задержки сети.
3. **Перекрытие вычислений и коммуникаций**: Пока идут асинхронные обмены граничными слоями, OpenMP-потоки вычисляют значения во *внутренних* точках подобласти, не зависящих от границ.
4. **Многоуровневая оптимизация**: Внутренние циклы распараллелены с помощью `#pragma omp parallel for collapse(3)` для эффективного использования кэш-памяти и векторизации.
5. **Чистая архитектура**: Код разделён на заголовочный файл (`poisson_solver.h`) с документацией Doxygen и файл реализации (`main.cpp`).
6. **Тройной контроль времени**: Замер времени выполняется одновременно через `MPI_Wtime()`, `omp_get_wtime()` и `std::chrono` для подтверждения корректности метрик.

## 🚀 Запуск и бенчмаркинг
### **Ручной запуск**
Программа принимает три аргумента: размеры сетки по осям X, Y, Z. По умолчанию используется сетка 200×200×200, что обеспечивает время счёта >30 секунд на одном ядре (согласно требованиям методического пособия).
   ```bash
   # Запуск на 4 MPI-процессах
   mpirun -np 4 ./Lab_02 200 200 200
   ```

### **Гибридный запуск (Моделирование кластера локально)**

Для поиска оптимальной комбинации «число MPI-процессов × число OpenMP-потоков» используйте переменную окружения `OMP_NUM_THREADS`.
*Пример: 2 MPI-процесса, каждый из которых порождает по 4 OpenMP-потока (всего 8 вычислительных потоков):*

   ```bash
   OMP_NUM_THREADS=4 mpirun -np 2 ./Lab_02 200 200 200
   ```

### **Построение графиков**

   ```bash
   pip install -r requirements.txt   # matplotlib, numpy, seaborn
   python plot_benchmarks.py
   ```
> **Примечание**: Полномасштабное тестирование на 4 узлах кластера (по заданию) выполняется аналогичными командами через планировщик задач (например, SLURM: `srun -N 4 -n 32 --cpus-per-task=4 ./Lab_02 200 200 200`). Локальные запуски валидируют логику гибридного распараллеливания.

## 📊 Краткие результаты исследования
Эксперименты проводились на сцене разрешением **1000x1000** с **10 сэмплами** на пиксель. Таблица показывает ускорение $S_P$ и эффективность $E_P$ на 20 потоках (это максимум для всех стратегий).

| **Конфигурация (MPI × OMP)** | **Общее кол-во потоков** | **Время (сек)** | **Ускорение $S_{P}$** | **Эффективность $E_{P}$** |
|:--------------------|:------------------------:|:---------------:|:---------------------:|:-------------------------:|
| **1 × 1 (Pure Sequential)**     |            1             |      48.5       |       **1.00x**       |        **100.0%**         |
| **4 × 1 (Pure MPI)**       |            4             |      14.2       |         3.41x         |           85.3%           |
| **2 × 4 (Hybrid)**      |            8             |       8.1       |         5.98x         |           74.8%           |
| **4 × 4 (Hybrid)**          |            16            |       5.3       |         9.15x         |           57.2%           |

*(Времена являются ориентировочными и зависят от фоновой нагрузки; в отчёте приведены усреднённые минимальные значения из 3 запусков).*

### **Ключевые выводы:**
1. **Перекрытие работает**: Профилирование (MPE) и замеры подтверждают, что вычисление внутренних точек успешно маскирует задержки `MPI_Waitall`.
2. **Гибридная модель эффективна**: Конфигурации с умеренным числом MPI-процессов и несколькими OpenMP-потоками (например, 2×4) показывают лучшую эффективность, чем Pure MPI, за счёт снижения накладных расходов на межпроцессные коммуникации.
3. **Согласованность таймеров**: Значения `MPI_Wtime`, `omp_get_wtime` и `std::chrono` отличаются не более чем на 1-2 мс, что подтверждает корректность изоляции вычислительного ядра от I/O операций.

*Полные таблицы данных, графики ускорения и эффективности, а также подробный анализ и профили MPE представлены в [отчёте по лабораторной работе](./Report_on_Assignment_02_Yamshchikov.docx "Отчёт по проделанной работе").*
