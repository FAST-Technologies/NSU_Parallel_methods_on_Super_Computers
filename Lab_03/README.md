# Лабораторная работа №3: Параллельное умножение матриц на GPU (CUDA)
## Сравнение методов Naive, Tiled (Shared Memory) и cuBLAS

Данный репозиторий содержит реализацию и исследование производительности трёх различных методов умножения квадратных матриц на графическом процессоре (GPU) с использованием технологии NVIDIA CUDA. Проект разработан в рамках учебного курса по параллельным методам вычислений.


---

## 📋 Описание и ключевые особенности

**Цель работы** — реализовать и сравнить производительность различных подходов к умножению матриц $C = A \times B$ на GPU, исследовать влияние размера блока потоков и решётки блоков на производительность, а также сравнить ручную оптимизацию с использованием разделяемой памяти против высокооптимизированной библиотеки cuBLAS.

**Реализованные методы:**

1. **Наивный алгоритм (Naive / Global Memory).**
   Каждый поток вычисляет один элемент результирующей матрицы $C_{ij}$, считывая всю $i$-ю строку матрицы $A$ и весь $j$-й столбец матрицы $B$ напрямую из глобальной памяти видеокарты.

2. **Блочный алгоритм (Tiled / Shared Memory).**
   Матрицы разбиваются на тайлы размером `BLOCK_SIZE × BLOCK_SIZE`. Потоки блока кооперативно загружают фрагменты в быструю разделяемую память (Shared Memory), синхронизируются через `__syncthreads()` и выполняют вычисления, многократно используя загруженные данные. Это снижает нагрузку на шину глобальной памяти в `BLOCK_SIZE` раз.

3. **Библиотека cuBLAS.**
   Использование высокооптимизированной аппаратной реализации от NVIDIA. Для исключения накладных расходов на инициализацию контекста применяется метод «прогрева» (warm-up). Библиотека задействует тензорные ядра (Tensor Cores) архитектуры Ada Lovelace.

**Основные особенности реализации:**

* **Три независимых ядра** в одном исполняемом файле для прямого сравнения на одних и тех же данных.
* **Чистая архитектура**: CUDA-ядра вынесены в отдельный заголовочный файл (`matrix_kernels.hpp`) с полной документацией Doxygen.
* **Гибкий запуск**: размер матрицы и размер блока передаются через аргументы командной строки, что позволяет проводить эксперименты без перекомпиляции.
* **Автоматическая верификация**: результаты GPU сравниваются с эталонным CPU-умножением (для матриц $N \le 512$).
* **Точные замеры времени**: используется механизм CUDA Events (`cudaEvent_t`) с микросекундной точностью.
* **Автоматизация экспериментов**: скрипт `benchmark.sh` тестирует различные комбинации размеров матриц и блоков.
* **Визуализация**: два Python-скрипта строят графики времени, ускорения и эффективности.
* **Генерация документации**: автоматическая сборка HTML-документации через Doxygen.

## 🛠️ Сборка проекта

1. Склонируйте репозиторий (если еще не сделали этого):
   ```bash
   git clone <URL этого репозитория>
   cd NSU_Parallel_methods_on_Super_Computers/Lab_03
   ```
2. Создайте директорию для сборки и перейдите в неё:
   ```bash
   mkdir build && cd build
   ```
3. Сконфигурируйте проект в режиме Release (с оптимизацией `-O3`):
   ```bash
   cmake .. -DCMAKE_BUILD_TYPE=Release
   ```
4. Скомпилируйте проект, используя все доступные ядра:
   ```bash
   make -j
   ```
5. Опционально. Сгенерировать Doxygen-документацию:
   ```bash
   make doc
   ```
Документация появится в `build/docs/html/index.html`.

## 🚀 Запуск и бенчмаркинг
### **Ручной запуск**
Программа принимает до двух аргументов:
1. **N** — размер квадратной матрицы (по умолчанию 1024).
2. **BLOCK_SIZE** — размер блока потоков (по умолчанию 32, берётся из `#define`).
   ```bash
     # Запуск с матрицей 1024×1024 и блоком 32×32
     ./build/Lab_03 1024
        
     # Запуск с матрицей 2048×2048 и блоком 16×16
     ./build/Lab_03 2048 16
   ```

Программа выведет время выполнения каждого из трёх методов и (для **N ≤ 512**) результат верификации.

### **Автоматический гибридный бенчмаркинг**

В корне проекта находится скрипт `benchmark.sh`, который автоматически тестирует различные комбинации размеров матриц (256, 512, 1024, 2048) и размеров блоков (16, 32). Для каждой конфигурации выполняется 3 запуска, берётся минимальное время.

   ```bash
   # Сделать скрипт исполняемым (один раз)
   chmod +x benchmark.sh
   
   # Запустить бенчмарк
   ./benchmark.sh
   ```

Скрипт выведет таблицу в терминал, которую можно напрямую скопировать в отчёт.

### Построение графиков

Установите необходимые зависимости Python:

```bash
python3 -m pip install matplotlib pandas seaborn numpy
```

Либо всё сразу одной командой:

```bash
# Вариант на чистом Matplotlib (без pandas/seaborn)
```

Результаты сохраняются в каталоге `visualisations/`:

* `cuda_speedup.png` — столбчатая диаграмма ускорения.

> **Примечание:** перед запуском проверьте, что скрипты действительно находятся в `visual_scripts/`. Если они размещены в другом каталоге, измените команды запуска соответственно.

### Основные выводы

1. **Эффективность GPU для задач линейной алгебры.** Перенос вычислений с CPU на GPU дал колоссальный прирост производительности. Оптимизированный блочный алгоритм (Shared Tiled) оказался быстрее последовательной реализации на CPU в ~1849 раз (для **N = 1024**). Это подтверждает, что архитектура GPU с тысячами вычислительных ядер идеально подходит для массово-параллельных задач.
2. **Роль разделяемой памяти (Shared Memory).** Использование блочного алгоритма (Tiling) позволило ускорить вычисления относительно наивной реализации GPU-кода. На малых матрицах (**N = 256**) ускорение составило **4.54×**, что демонстрирует эффективность снижения нагрузки на глобальную память. На средних и больших матрицах (**N ≥ 1024**) ускорение стабилизировалось на уровне **1.2× – 1.44×**. Снижение разрыва на больших задачах объясняется архитектурными особенностями RTX 4060: большой объём L2-кэша видеокарты эффективно «скрывает» задержки глобальной памяти даже в наивном алгоритме.
3. **Специализированные аппаратные блоки (Tensor Cores).** Библиотека cuBLAS показала наилучшие результаты, обогнав даже оптимизированную вручную версию в **10–20 раз**. Это связано с использованием тензорных ядер (Tensor Cores) — специализированных блоков архитектуры NVIDIA, которые перемножают целые матрицы за один такт, в то время как универсальные CUDA-ядра выполняют одну операцию над парой чисел за такт.
4. **Влияние размера блока.** Эксперименты с размерами блока 16×16 и 32×32 показали, что для RTX 4060 больший блок (32×32) даёт незначительное преимущество за счёт лучшего использования L1-кэша и меньшего числа вызовов `__syncthreads()`. Однако на очень малых матрицах разница минимальна.

Результаты относятся к конкретной конфигурации вычислительной среды и размеру матриц. Для другого оборудования и версий CUDA оптимальные параметры могут отличаться.
