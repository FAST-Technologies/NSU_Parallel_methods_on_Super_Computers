# Лабораторная работа: динамическая балансировка нагрузки с MPI и POSIX Threads

## Описание проекта

Проект реализует распределённое выполнение набора независимых задач с динамической балансировкой нагрузки. Для распределения работы между процессами используется **MPI**, а для параллельного выполнения задач внутри каждого процесса — **POSIX Threads (pthreads)**.

В каждом MPI-процессе создаются четыре Worker-потока, один Fetcher и один Responder.

- **Worker** извлекает задачи из локальной общей очереди и выполняет их.
- **Fetcher** при опустошении локальной очереди запрашивает дополнительные задачи у других MPI-процессов.
- **Responder** обрабатывает входящие запросы и при наличии задач передаёт часть локальной очереди запрашивающему процессу.

Общая очередь защищена мьютексом. Для координации потоков используются условные переменные POSIX Threads.

## Архитектура

```text
Один MPI-процесс
+----------------------------------------+
|              Общая очередь             |
|                                        |
| Worker 1   Worker 2   Worker 3 Worker 4|
|                                        |
| Fetcher                 Responder      |
+----------------------------------------+
          | MPI-запросы / ответы |
          v                      v
                 Другие MPI-процессы
```

### Синхронизация потоков

| Примитив | Назначение |
|---|---|
| `pthread_mutex_t` | Защита общей очереди и связанных общих данных |
| `c_jobAdded` | Оповещение Worker о появлении новых задач |
| `c_needToFetch` | Оповещение Fetcher об опустошении локальной очереди |

Worker ожидают появления задач на `c_jobAdded`, а Fetcher ожидает сигнала о необходимости запросить дополнительную работу на `c_needToFetch`. Ожидание условных переменных выполняется с использованием соответствующего мьютекса.

MPI инициализируется с требованием `MPI_THREAD_MULTIPLE`, поскольку MPI-вызовы могут выполняться из нескольких потоков одного процесса.

## Требования

Проверенная среда:

- Ubuntu 24.04 LTS / WSL2;
- GCC 13.3 или совместимый C++17-компилятор;
- OpenMPI 4.1.x;
- CMake 3.20 или новее;
- POSIX Threads;
- Doxygen 1.9+ (для документации);
- Graphviz (необязательно, для графов).

Установка зависимостей в Ubuntu:

```bash
sudo apt update
sudo apt install build-essential cmake openmpi-bin libopenmpi-dev

```

## Сборка

Из корневого каталога проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Исполняемый файл будет создан по пути `build/dwsp`.

Чтобы собрать проект без настройки документации:

```bash
cmake -S . -B build -DBUILD_DOC=OFF
cmake --build build -j
```

## Запуск

Программа принимает два аргумента:

1. `N` — общее количество задач;
2. `BASE_MS` — базовая длительность задачи в миллисекундах.

Примеры:

```bash
mpirun -np 1 ./build/dwsp 100 50
mpirun -np 2 ./build/dwsp 100 50
mpirun -np 4 ./build/dwsp 100 50
```

Если MPI сообщает о недостаточном количестве доступных слотов, в тестовой среде можно использовать:

```bash
mpirun --oversubscribe -np 4 ./build/dwsp 100 50
```

`--oversubscribe` разрешает запуск большего числа MPI-процессов, чем доступно слотов, но не добавляет вычислительные ядра и может повлиять на время выполнения.

## Экспериментальные результаты

Один из выполненных наборов запусков: 100 задач, параметр `BASE_MS = 50`.

| MPI-процессы | Всего задач | Выполнено | Передано | Время, с |
|---:|---:|---:|---:|---:|
| 1 | 100 | 100 | 0 | 3.138750 |
| 2 | 100 | 100 | 0 | 1.604300 |
| 4 | 100 | 100 | 13 | 0.904525 |

Ускорение рассчитывается относительно запуска с одним процессом:

\[
S_p = \frac{T_1}{T_p}
\]

Эффективность:

\[
E_p = \frac{S_p}{p}\cdot 100\%
\]

| MPI-процессы | Ускорение | Эффективность |
|---:|---:|---:|
| 1 | 1.00 | 100% |
| 2 | 1.96 | 98.0% |
| 4 | 3.47 | 86.7% |

Это единичные измерения, а не средние значения серии повторов. Поскольку каждый MPI-процесс создаёт четыре Worker-потока, результаты характеризуют масштабирование всей гибридной конфигурации MPI + pthreads.

## Примечания

- Число Worker-потоков задаётся константой `WORKER_COUNT` в исходном коде.
- Число MPI-процессов задаётся параметром `-np` команды `mpirun`.
- При четырёх MPI-процессах создаётся 16 Worker-потоков, четыре Fetcher и четыре Responder.
- Сигнал Fetcher об отсутствии дополнительной работы не означает, что все Worker уже завершили вычисления: они могут выполнять ранее извлечённые задачи.
- Завершение программы определяется после учёта выполнения всех задач.
